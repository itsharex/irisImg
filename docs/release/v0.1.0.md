# irisImg v0.1.0 发布说明

> **版本**：v0.1.0（初版）
> **发布日期**：2026-07-25
> **代号**：初版释放（First Release）
> **产物**：`irisImg-0.1.0-linux-amd64.tar.gz`

irisImg 是一个面向个人使用的图床服务：前后端分离，后端 Go(Gin) 单二进制 + 纯 Go SQLite，前端 Nuxt 4 SPA，Nginx 同域反代。除「本人登录后台管理」外，另提供一套独立的 **API 密钥**鉴权体系，供外部程序「添加图片」，并内建日志中心与仪表盘。

v0.1.0 是项目的第一个正式版本，覆盖了登录、内容中心、APIkey 管理、日志中心、仪表盘、系统配置六大后台模块，以及从源码到上线的完整部署发布链路，并完成了首轮安全加固。本文档汇总本次释放的功能特性、技术栈、安全要点、接口、部署与已知限制；逐文件实现细节见 [`docs/`](../) 下对应文档。

## 一、功能特性

### 1. 登录认证（单用户 · JWT）

- **单用户模型**：账号信息直接写在 `config.yaml` 的 `auth` 段，无用户表、无会话存储，状态全部装在 JWT 里。
- **HS256 签名**：对称密钥够用，载荷含 `username / iss / sub / iat / nbf / exp`；服务端校验时**显式断言 HMAC**，防 `alg=none` 与公钥伪造。
- **常量时间比较**：登录用 `crypto/subtle.ConstantTimeCompare` 比对用户名与密码，两项都比对完才返回，防时序攻击。
- **统一 401**：登录失败、token 缺失/错误/过期对外都是 `401 / code=40100`，不暴露具体原因，防用户名枚举。
- **无感校验**：`GET /auth/me` 既能取当前用户，也充当 token 有效性探针。
- 详见 [`backend/AUTH.md`](../backend/AUTH.md)、[`frontend/AUTH.md`](../frontend/AUTH.md)。

### 2. 内容中心（图片浏览与后台直传）

- **图片网格浏览**：按 API Key 筛选、时间升序分页，点击查看大图与完整元数据（尺寸、MIME、hash、来源、上传时间）。
- **后台直传**：内容中心拖拽上传，走 JWT 鉴权的 `POST /admin/images`，`key_id` 留空（admin 直传）。
- **SHA256 去重**：文件名由内容 SHA256 计算，同一张图二次上传自动秒传、复用首次记录，不重复写盘。
- **真实 MIME 嗅探**：`http.DetectContentType` 看头部 512 字节 + 白名单，不信任客户端 `Content-Type`，扩展名由后端推导。
- **原子写盘**：写到同目录临时文件再 `os.Rename`，避免半写状态被读取；落盘 `0644` 保证 Nginx 跨用户可读。
- **目录分层**：按 `<root>/<YYYY>/<MM>/<sha256>.<ext>` 排布，避免单目录文件过多。
- 详见 [`backend/IMAGE.md`](../backend/IMAGE.md)。

### 3. API Key 管理（外部程序鉴权）

- **独立于 JWT**：密钥用于外部程序「添加图片」，管理接口需后台 JWT 登录，图片接口用密钥鉴权，两套互不依赖。
- **明文只给一次**：明文密钥 = 32 字节随机数经 base64url（43 字符），仅在创建/重置响应里返回一次；库里只存 **SHA-256 哈希**，无法反推。
- **两种权限**：`readonly`（只读，仅 GET）/ `readwrite`（可 POST 添加图片），校验顺序为「有效性 → 权限 → 限流」。
- **完整生命周期**：创建 / 重命名 / 重置明文（同时取消吊销重新激活）/ 吊销（软删除）/ 删除（物理删除并级联清理关联图片的物理文件与记录）。
- **按密钥限流**：每把密钥一个内存令牌桶，默认 100 次/分钟，超限 `429`。
- **密码二次确认**：吊销与删除为敏感操作，请求体需携带 `{username, password}`，`ConstantTimeCompare` 校验，失败返 **403**（而非 401，避免前端误判 JWT 失效而全局登出）。
- **HTTPS 强制**：`apikey.https_only` 开启时，密钥管理与日志清理接口要求 HTTPS。
- 详见 [`backend/APIKEY.md`](../backend/APIKEY.md)。

### 4. 日志中心（访问日志 + 业务审计）

- **统一日志表**：每个 HTTP 请求、每次 panic、每个关键业务动作（登录 / 上传 / 密钥签发·吊销·删除 / 日志清理）都落进同一张 `logs` 表，按 `event` 区分。
- **zap 强类型内核**：访问日志与运行时日志统一走 `*zap.Logger`，类型化 `zap.Field` 构造器避免 `interface{}` 装箱，输出到 stdout / 文件供运维采集。
- **异步批量落库**：容量 2048 的缓冲通道 + 后台 flusher 协程，攒满 200 条或满 1 秒一次性 `BatchCreate`，**请求处理零 DB 写延迟**；缓冲满则丢弃 + 告警，**绝不阻塞请求**。
- **request id 串联**：每个请求生成/透传 `X--Request-Id`，同一请求的访问日志、业务事件、panic 经 `request_id` 关联。
- **多维查询**：分页 + 按级别 / 事件 / 方法 / 状态类（2xx/4xx/5xx）/ 关键字 / 起止日期 / request_id / api_key_id 过滤。
- **14 天直方图**：纯 SVG 绘制，缺日补零，带 7 日移动平均趋势线，零第三方依赖。
- **清理留审计**：清空日志前先同步 flush 在途日志，清空后补记一条 `event=log.clear` 审计事件（含删除条数），证明「日志被清过」与「谁清的」。
- **日志注入防护（CWE-117）**：DAO 写入边界对可控字段统一过 `sanitizeLogText`，把 CR/LF 替换为空格，防伪造换行。
- 详见 [`backend/LOG.md`](../backend/LOG.md)。

### 5. 仪表盘（聚合统计）

- **单接口聚合**：`GET /admin/dashboard?days=30` 一次性返回图片总量、存储占用、APIkey 计数（有效/已吊销）、日志总量与近 N 天上传趋势，避免前端发多个请求拼装。
- **存储占用 = DB `SUM(size)`**：以 `images.size` 为单一事实来源，一条 SQL 快速准确，规避文件系统遍历的慢与孤儿文件问题；空表 SUM 返回 NULL 有兜底。
- **趋势以 `Image.CreatedAt` 为准**：而非 `image.upload` 日志事件数（秒传也会记事件导致重复计数，且日志可被清空不持久）。
- **按来源拆分**：近 N 天新增趋势按 API Key / 后台直传来源拆分计数，hover 浮动卡展示当日每个 key 上传数，admin 直传显示 `admin`。
- **复用 LogsHistogram**：前端趋势图复用日志中心直方图组件，统计卡片 + 趋势图 + 四中心快捷入口。
- 详见 [`backend/DASHBOARD.md`](../backend/DASHBOARD.md)。

### 6. 系统配置（只读快照）

- **脱敏只读**：`GET /system/config` 返回当前运行配置快照，剔除 `auth.password` / `auth.username` / `jwt.secret`，`database.dsn` 剥离查询串只留纯路径。
- **回退生效默认**：0/负数配置值回退到生效默认值展示，反映真实运行态。
- **HTTPS 警告**：`https_only=false` 时前端顶部渲染橙色警告条。
- 无写操作、无热更新；仅 `JWT` 保护（未套 HTTPSOnly），开发环境 HTTP 亦可访问。
- 详见 [`backend/internal/api/system.md`](../backend/internal/api/system.md)。

## 三、安全特性

v0.1.0 在初版即内建了较完整的纵深防御，安全审查与加固集中在 PR #15 / #16：

- **release 模式 fail-closed 启动校验**：`config.Validate()` 在 release 模式下拒绝默认口令（`admin123`）/ 空口令、弱 JWT 密钥（默认占位串 / 空 / 长度 <32）、通配 CORS（`*`），闭合「拷贝模板未改口令即上线」与「通配 CORS 上线」两条攻击链。
- **`/imgs` 静态旁路纵深防御**：静态服务带图片扩展名白名单（仅放行 `.png/.jpg/.jpeg/.gif/.webp` 等），即便 `root_dir` 被误配成工作目录，未认证访客也无法经 `/imgs` 下载 `config.yaml` / 数据库 / 源码；目录列表与 `..` 逃逸同样被挡。Nginx 模板 `/imgs/` 块同步加正则守卫，前后端双重防御。
- **`root_dir` 误配 fail-fast**：`storage.NewSaver` 启动期拒绝 `root_dir` 指向 cwd 本身或其祖先（`.` / `..` / `/` / 工作目录父级），错配启动即失败而非静默暴露。
- **HTTPSOnly 信任边界**：不再无条件信任 `X-Forwarded-Proto`，仅当 TCP 对端属于 `server.trusted_proxies` 网段时才认该头，否则只认 `c.Request.TLS`；后端端口误暴露公网时伪造头无法绕过 HTTPS 校验。
- **CORS origin 白名单**：收紧为按 `cors.allow_origins` 配置的 origin 白名单，release 模式拒 `*`，空列表关闭跨域（生产同域最安全）。
- **敏感操作密码二次确认返 403**：密钥吊销/删除、日志清理需 `{username, password}` 二次确认，失败返 **403** 而非 401，前端不会误判 JWT 失效而全局登出，由调用方就地提示。
- **常量时间比较**：登录与所有密码二次确认均用 `subtle.ConstantTimeCompare`，防时序攻击。
- **JWT 显式断言 HMAC**：`Parse` 强制 `*jwtv5.SigningMethodHMAC`，防 `alg=none` 与 RS256 公钥伪造。
- **API Key 哈希存储**：库里只存 SHA-256 哈希，泄露库文件不会直接暴露明文；明文等价口令，泄露需立即吊销重建。
- **真实 MIME 嗅探**：不信任客户端 `Content-Type`，伪造无效。
- **日志注入防护（CWE-117）**：DAO 写入边界统一 sanitize CR/LF。
- **接口层脱敏**：`SystemConfigResponse` 结构根本无 `Auth` 字段；访问日志不记请求体；无 pprof/debug 路由；panic 返回通用消息。

## 四、接口一览

所有业务接口挂在 `/api/v1` 下，统一响应体 `{ code, message, data }`。

```
/imgs/*filepath                   GET/HEAD    静态图片服务（仅放行图片扩展名）

/api/v1
├── GET  /ping                   公开        健康检查
├── POST /auth/login             公开        登录，返回 JWT
├── ── (JWTAuth)
│   ├── GET  /auth/me            受保护      当前用户 / token 探针
│   ├── GET  /admin/images       受保护      后台图片列表（可按 key_id 筛选）
│   ├── POST /admin/images       受保护      后台直传上传（key_id=nil）
│   ├── GET  /system/config      受保护      系统配置只读快照
│   ├── GET  /admin/dashboard    受保护      仪表盘聚合统计（?days=30）
│   ├── ── (HTTPSOnly) /apikeys
│   │   ├── POST   ""            JWT+HTTPS   创建密钥（响应含一次性明文）
│   │   ├── GET    ""            JWT+HTTPS   列出全部密钥
│   │   ├── PATCH  "/:id"        JWT+HTTPS   重命名
│   │   ├── POST   "/:id/reset"  JWT+HTTPS   重置明文（同时取消吊销）
│   │   ├── POST   "/:id/revoke" JWT+HTTPS+密码   软吊销
│   │   └── DELETE "/:id"        JWT+HTTPS+密码   硬删 + 级联删图
│   └── ── (HTTPSOnly) /admin/logs
│       ├── GET    ""            JWT+HTTPS   分页 + 多维过滤查询
│       ├── GET    "/histogram"  JWT+HTTPS   14 天每日日志量
│       └── DELETE ""            JWT+HTTPS+密码   清空全部日志
└── ── (APIKeyAuth) /images
    ├── GET  ""                  API Key     申请图片（占位，返回 501）
    └── POST ""                  API Key     添加图片（需 readwrite）
```

错误码：`0` 成功 / `40000` 入参非法 / `40100` 未登录或凭据错 / `40110` 缺 X-API-Key / `40120` 密钥无效 / `40300` 禁止（只读写、未走 HTTPS、密码二次确认失败）/ `40400` 不存在 / `413` 文件过大 / `42900` 限流 / `50000` 服务器内部错误。

端到端链路见各特性文档：[AUTH](../backend/AUTH.md) / [APIKEY](../backend/APIKEY.md) / [IMAGE](../backend/IMAGE.md) / [LOG](../backend/LOG.md) / [DASHBOARD](../backend/DASHBOARD.md)。

## 五、部署与升级

### 部署形态

- **后端**：Go 单二进制（`CGO_ENABLED=0` 交叉编译，linux/amd64），纯 Go SQLite 无需 CGO，监听 `0.0.0.0:8080`（生产建议 `127.0.0.1` 仅本机反代访问）。
- **前端**：Nuxt4 SPA，`pnpm generate` 产出纯静态站点，由 Nginx 直接 serve。
- **反代**：Nginx 同域反代，`/api/` 转发后端（无尾斜杠保留 `/api` 前缀）、`/imgs/` 直接 serve 落盘目录、`/` serve 前端 SPA。

### Release 产物结构

```
irisImg/
├── irisImg                       # 后端二进制（linux/amd64）
├── config/config.yaml.example    # 配置模板（首次部署 cp 为 config.yaml 再改）
├── web/                          # 前端 SPA 静态产物
├── data/                         # 运行时数据（db + imgs，运行时生成）
├── nginx/                        # Nginx 示例配置（.conf.example，HTTPS 生产 + HTTP 最简）
└── scripts/                      # start.sh / stop.sh / irisImg.service
```

### 首次部署要点

1. 解压到 `/opt/irisImg`，`cp config/config.yaml.example config/config.yaml`。
2. **必改**：`auth.username` / `auth.password` / `auth.jwt.secret`（≥32 字节随机串）—— release 模式默认值会被 `Validate` 拒绝启动。
3. `server.host` 改 `127.0.0.1`（仅本机反代）；`apikey.https_only: true`；`cors.allow_origins` 留空（同域最安全）。
4. `storage.root_dir` 与 Nginx `/imgs/` alias 指向同一物理目录，落盘文件 0644、目录 0755。
5. 用 systemd 或 `start.sh` 启动；Nginx 套用 `nginx/irisImg.conf.example`（HTTPS）。

### 升级

整包解压会覆盖二进制、`web/`、`scripts/`、`nginx/*.example` 等随包文件，但 `config/config.yaml` 与 `data/` 不在 release 包内、不会被覆盖。升级后请 `diff config/config.yaml config/config.yaml.example` 合并新增键，否则缺失键在运行时取零值（关键键如 `storage.root_dir` 缺失会导致启动失败）。

### 构建脚本

打包脚本 [`scripts/build-release.sh`](../../scripts/build-release.sh)，产物输出到 `dist/`（已 gitignore）。已内置两层构建坑防护：

- **Git Bash (MSYS2) 路径转换污染**：`NUXT_PUBLIC_API_BASE=/api/v1` 在 Windows Git Bash 下会被改写成盘符路径烤进产物，部署后登录 `Failed to fetch`。防护：`MSYS_NO_PATHCONV=1` + `nuxt.config.ts` 的 `sanitizeApiBase()` 兜底 + 构建后 grep 产物校验。
- **随包脚本 CRLF 行尾**：Windows `autocrlf=true` 会让 `.sh`/`.service` 变 CRLF，Linux 执行报 `bash\r: No such file or directory`。防护：`.gitattributes` 钉 `*.sh`/`*.service` 为 `eol=lf` + 打包时 `sed 's/\r$//'` 剥 CR + `tar --mode='0755'` 强制执行位。

部署清单与排错见随包分发的 `deploy/README.md`；整体部署架构与反代约定见 [`deploy.md`](../deploy.md)。

## 六、配置速览

配置文件 `config/config.yaml`，可用 `IRIS_CONFIG` 环境变量指向私有副本。缺省默认由 `config.ApplyDefaults()` 在加载阶段集中补齐（单一事实源）。关键字段：

| 段.字段 | 默认 | 说明 |
| --- | --- | --- |
| `server.host` / `server.port` / `server.mode` | `0.0.0.0` / `8080` / `debug` | 监听地址、端口、Gin 模式 |
| `server.trusted_proxies` | `[127.0.0.1/8, ::1]` | 受信任反代 CIDR，HTTPSOnly 仅对此列表认 `X-Forwarded-Proto` |
| `app.version` | `0.1.0` | 版本号（出现在 `/ping` 响应） |
| `auth.username` / `auth.password` | `admin` / `admin123` | 单用户账密（release 模式默认值会被拒绝启动，必改） |
| `auth.jwt.secret` / `issuer` / `expire_hours` | 占位串 / `irisImg` / `24` | HS256 密钥（release 模式 <32 字节会被拒绝，必改）/ 签发者 / 有效期 |
| `database.driver` / `dsn` / `auto_migrate` | `sqlite` / `data/irisImg.db?...` / `true` | 纯 Go SQLite，DSN 带 WAL/busy_timeout/foreign_keys pragma |
| `apikey.rate_limit_per_minute` / `https_only` | `100` / `false` | 单密钥限流阈值 / 是否强制 HTTPS（生产 true） |
| `storage.root_dir` | `data/imgs` | 图片落盘根目录（fail-fast：拒绝指向 cwd 本身/祖先） |
| `storage.public_base_url` | `""` | 空 → `/imgs/<rel>` 同域反代；非空 → 绝对前缀（须带协议，裸域名自动补 `https://`） |
| `storage.max_upload_size_mb` | `20` | 单次上传字节上限（MiB） |
| `storage.allowed_mime_types` | `png/jpeg/gif/webp` | 真实 MIME 白名单（后端嗅探） |
| `cors.allow_origins` | `["*"]` | 开发 `*`；生产留空关闭或配确切域名（release 模式拒 `*`） |
| `logger.level` / `encoding` / `output` / `time_format` | `info` / `json` / `stdout` / `iso8601` | zap 输出配置（访问日志另异步落库） |

完整字段说明见 [`backend/config/config.md`](../backend/config/config.md)。

- **#11 仪表盘**：将 `/dashboard` 占位页改造为真实仪表盘，后端 `GET /admin/dashboard` 一次性返回聚合统计（图片总量 / 存储占用 / APIkey 计数 / 日志总量 / 近 N 天上传趋势）；前端渲染统计卡片、趋势图与四中心快捷入口，复用 `LogsHistogram`。
- **#12 部署与发布打包**：补齐从源码到上线的部署发布能力——一键 `build-release.sh` 交叉编译 + 前端 `pnpm generate` + 组装 `.example` 模板打包；release 模式 `config.Validate()` fail-closed；systemd/nginx/start.sh 加固（降权、预检、限流、安全头）。
- **#17 仪表盘趋势按来源拆分**：趋势图按 API Key/后台直传来源拆分计数（后端 `RecentUploadTrend` 追加按 `key_id` 分组的 `Keys`）；前端 `LogsHistogram` hover 改造为透明热区 + 悬停竖直虚线 + 浮动信息卡展示来源明细；顺带修复浮窗宽度与虚线颜色两个 bug。

### 修复与加固

- **#13 修复生产图片不显示**：落盘图片 0600 权限致 Nginx 跨用户读取 403（`os.Rename` 后显式 `os.Chmod(0o644)`，秒传分支幂等纠正历史 0600）；`public_base_url` 配成裸域名致前端 src 拼接异常（`NewSaver` 自动补 `https://`）；随包脚本 CRLF 致 Linux `bash\r` 报错（`.gitattributes` 钉 LF + `sed` 剥 CR）。
- **#14 集中缺省默认到 ApplyDefaults**：新增 `(*Config).ApplyDefaults()` 集中补齐缺省字段，修复两个静默 bug——`storage.allowed_mime_types` 缺失致上传全拒、`server.port` 缺失致监听随机端口；fail-fast 字段与安全字段刻意不兜底。
- **#15 `/imgs` 静态旁路纵深防御**：堵住 root_dir 误配时未认证下载 `config.yaml`/整库的漏洞——新增 `router/static.go` 扩展名白名单静态服务、`NewSaver` 启动期 `guardRootDir` fail-fast、Nginx `/imgs/` 块同步加正则守卫。
- **#16 HTTPSOnly 信任边界 + CORS 白名单 + 启动探测**：HTTPSOnly 新增 `isFromTrustedProxy` 校验 TCP 对端（仅可信反代 CIDR 才认 `X-Forwarded-Proto`）；CORS 引入 `gin-contrib/cors` 收紧为 origin 白名单（release 模式拒 `*`）；顺带修复 `start.sh` 启动假成功（轮询进程存活，失败回显日志末尾 + exit 1）。

## 八、已知限制与不在本次范围

以下为 v0.1.0 的已知边界，使用前请知悉：

- **对外图片列表/单图查询未实现**：`GET /api/v1/images` 当前固定返回 501 占位，对外列表 / 单图查询语义待定。后台列表已通过 `GET /admin/images`（JWT）落地。
- **单用户模型**：账号写死在 `config.yaml`，密码明文存储（非 bcrypt 哈希）；无用户表、无注册、无多用户。
- **无 refresh token**：token 过期后只能让用户重新登录；前端 token 存 `localStorage`。
- **内存限流 / 内存日志缓冲不抗多实例与重启**：进程重启时缓冲内未 flush 的日志丢失；多实例部署需换共享队列（如 Redis Stream / Kafka）与共享限流。
- **日志仅支持一键清空**：无按天保留 / TTL / 归档；`GET /api/v1/ping` 健康检查不入日志中心。
- **仪表盘无缓存**：`Overview` 含 30 天循环 `CountByRangeGrouped`，SQLite 本地首版足够快；数据量增大后建议加内存缓存或改为单条 `GROUP BY` 聚合。
- **存储占用为 DB `SUM(size)`**：不含孤儿文件；磁盘实际占用（`filepath.Walk`）未提供。
- **未实现**：缩略图、EXIF 清理、防盗链、对象存储后端、MIME 类型分布、APIkey 活跃度、bcrypt 密码哈希、refresh token。
- **跨机反代需追加 CIDR**：`server.trusted_proxies` 默认本地回环，跨机反代需追加反代所在 CIDR，否则 HTTPSOnly 不认 `X-Forwarded-Proto`。
